# Agent Workload Deployment Changes

This document records all repository file changes made on the `coach-deployment` branch relative to
`upstream/main`, including the fixes made while deploying and validating the workload end to end.

| File | Change | Reason |
|---|---|---|
| [`challenges/contribution-01-apim-gateway.md`](challenges/contribution-01-apim-gateway.md) | Added a design note for routing model traffic through APIM, emitting token metrics, enforcing token limits, and optionally adding model load balancing. | APIM was provisioned but no application traffic used it. The document captures the proposed work needed to make APIM a real GenAI gateway. |
| [`challenges/contribution-02-control-tower-actuation.md`](challenges/contribution-02-control-tower-actuation.md) | Added a design note for using Fabric Activator, a pipeline, and an Azure actuator to apply guarded APIM policy changes and write interventions back to OneLake. | The Control Tower currently observes and alerts but does not act. This proposal describes how to close the detect-act-verify loop. |
| [`resources/agent-workload/.gitignore`](resources/agent-workload/.gitignore) | Added `.npmrc` to ignored files. | The local `.npmrc` can contain an internal Microsoft package-feed URL or authentication-related configuration and must not be committed. |
| [`resources/agent-workload/src/frontend/Dockerfile`](resources/agent-workload/src/frontend/Dockerfile) | Made `.npmrc` an optional input to the dependency stage and changed dependency installation to `npm ci \|\| npm install`. | The managed corporate network blocked the public npm registry, so local Docker builds needed the approved registry configuration. The fallback supports the repository's current lack of a `package-lock.json`; `npm ci` fails without one and `npm install` continues the build. |
| [`resources/agent-workload/infra/main.bicep`](resources/agent-workload/infra/main.bicep) | Changed the default Azure OpenAI deployment from `gpt-4o` to `gpt-5-mini`; added configurable model-version and SKU parameters with defaults `2025-08-07` and `GlobalStandard`; enabled Key Vault purge protection; and removed the top-level ACR `AcrPull` assignment after moving it into the Container Apps module. | The original model versions were unavailable or deprecating in Sweden Central, tenant policy required Key Vault purge protection, and the top-level `AcrPull` assignment ran only after the Container Apps module, creating an ordering problem for apps configured to use that identity with ACR. |
| [`resources/agent-workload/infra/modules/container-apps.bicep`](resources/agent-workload/infra/modules/container-apps.bicep) | Moved the managed identity's deterministic `AcrPull` role assignment into this module immediately after ACR creation and made all three apps depend on that assignment. The application target ports remain `3000`, `8000`, and `8001`, and `minReplicas` remains `1`. | Moving `AcrPull` establishes registry authorization before Container App creation instead of waiting for the entire module to finish. Temporary experiments with `minReplicas: 0` and placeholder port 80 were reverted after Azure proved the apps could finish provisioning with their intended ports and an always-running replica was preferred to avoid cold starts. |
| [`resources/agent-workload/src/agent/app.py`](resources/agent-workload/src/agent/app.py) | Changed the fallback deployment name from `gpt-4o` to `gpt-5-mini` and the Azure OpenAI API version from `2024-10-21` to `2025-04-01-preview`. | The agent defaults must match the model deployed by Bicep, and the newer model requires a compatible Azure OpenAI API version. |
| [`resources/agent-workload/infra/modules/api-management.bicep`](resources/agent-workload/infra/modules/api-management.bicep) | Changed `allow-credentials` from `true` to `false` in the frontend, backend, and agent API CORS policies while retaining wildcard origins. | APIM rejects wildcard origin `*` when credentialed CORS is enabled. These APIs do not require browser cookies or credentialed cross-origin requests, so disabling credentialed CORS makes all three policies valid. |
| [`resources/agent-workload/src/backend/requirements.txt`](resources/agent-workload/src/backend/requirements.txt) | Added `aiohttp==3.11.11`. | The asynchronous Azure Cosmos client requires `aiohttp`. Without it, the backend exited during startup with `ImportError: aiohttp package is not installed` and entered `CrashLoopBackOff`. |
| [`resources/agent-workload/src/backend/app.py`](resources/agent-workload/src/backend/app.py) | Added the configurable `COSMOS_DATABASE` setting with default `agentsdb`; replaced the stale hardcoded `observability-demo` database name; removed unsupported `enable_cross_partition_query` arguments from asynchronous Cosmos queries; and changed the backend-to-agent payload to send `messages` plus `session_id`. | Bicep provisions `agentsdb`, not `observability-demo`; the stale name caused Cosmos 404 responses. The async Cosmos SDK rejected the synchronous-SDK query option. The old agent payload used `message` and `conversationId`, which did not match the agent's `AgentRequest` model and returned HTTP 422. |
| [`resources/agent-workload/src/frontend/src/app/page.tsx`](resources/agent-workload/src/frontend/src/app/page.tsx) | Loads the backend URL at runtime from `/api/config`; sends `{ "title": "New Conversation" }` when creating a conversation; and reads the reply from `assistantMessage.content`. | `NEXT_PUBLIC_API_URL` was previously resolved during the container build, where the Azure backend URL was unavailable, causing the browser bundle to use localhost. Conversation creation omitted the backend's required `title`, causing HTTP 422, and the frontend expected a response shape different from the backend's actual contract. |
| [`resources/agent-workload/src/frontend/src/app/api/config/route.ts`](resources/agent-workload/src/frontend/src/app/api/config/route.ts) | Added a dynamic server-side endpoint that reads `NEXT_PUBLIC_API_URL` from the running Container App environment and returns it to the browser. It returns HTTP 500 when the variable is absent. | The same frontend image must use deployment-time Container App configuration rather than embedding an environment-specific backend URL during `next build`. |

## Validation Performed

- Compiled the complete Bicep template successfully after the infrastructure and APIM changes.
- Built the agent, backend, and frontend images remotely in Azure Container Registry because local
  Docker package downloads were blocked by managed network TLS policy.
- Verified healthy agent, backend, and frontend Container App revisions.
- Created a conversation in Cosmos DB and sent `Hi` through the backend.
- Verified the backend invoked the agent, the agent invoked Azure OpenAI, and the response
  `Hello! How can I help you today?` returned successfully.
- Verified the deployed frontend workflow works end to end.

## Deployment Note

The remote images were deployed with explicit tags during troubleshooting, culminating in
`backend:dt6` for the backend contract and Cosmos fixes. Azure deployment operations, ACR image tags,
and test records in Cosmos DB are runtime changes; they are not additional repository file changes.
